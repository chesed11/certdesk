# 证书管理与恢复工作台

这是面向 Linux / Certbot / Nginx 的本地原型。工作台提供证书台账、真实 HTTPS 检查及系统续期报告展示；独立的 systemd 定时任务负责按管理员的固定策略调用 Certbot。项目尚未在你的服务器完成端到端验证，**请先在隔离测试环境演练，不要直接用于生产**。

目前适合用于体验流程、技术验证和反馈；没有安全修复时限或持续维护承诺。

## 启动工作台

需要 Python 3.9 或更高版本，不需要第三方 Python 库。Windows 可查看台账和检测 HTTPS；受控续期执行器需要 Linux、systemd、Certbot 和 Nginx。

- Windows：双击 `start.bat` 或运行 `py server.py`。
- Linux：以普通用户在本目录运行 `python3 server.py`；不要使用 root 身份运行 Web 界面。

浏览器访问 `http://127.0.0.1:8765`，在登录框输入服务启动终端显示的访问码；每次启动会生成新的访问码。终端与会话需要妥善保护。服务仅监听本机；远程 Linux 可在可信电脑上使用 `ssh -L 8765:127.0.0.1:8765 用户名@服务器地址`，再访问本机地址。不要将端口暴露到公网或共享转发。

关闭工作台不会关闭已经独立安装的 systemd 定时器。台账与检测数据保存在 `data/certificates.db`；首次启动生成演示数据。更新项目请保留整个 `data` 文件夹，备份前停止工作台。删除证书会同时删除其人工事件。

## 真实续期与权限隔离

完整安装步骤、前提、权限检查、测试及停用方式见 **DEPLOY-LINUX.md**。管理员需先配置本机已有的 Certbot 证书、无人值守验证及 Nginx 部署 hook；固定策略由 root 管理，Web 用户不能修改或启动续期。使用受控 systemd 定时器，不依赖 Web 进程；先检查已有 Certbot 任务，避免两套任务管理同一证书。首次手动启动服务就是实际续期检查，可能运行已有 hook 并改变服务，不是无副作用测试。

执行器检查续期结果及本地证书和 HTTPS 端点，并报告验证状态；超时可能触发受控恢复流程。具体行为和边界以部署指南为准。结果为失败、超时或待确认时应检查日志并人工处置；单个端点验证不能代表负载均衡后的所有节点。命令成功不自动意味着线上证书已更换或所有服务正常。

## 安全与限制

工作台访问码是本地会话保护，不是完整的企业用户管理或角色授权；可读取终端输出、浏览器会话或运行账户数据的人可能获得访问。项目没有多用户隔离、外部告警、跨节点部署或自动回滚。请勿录入私钥、密码、令牌或其他敏感凭据；Certbot 自身按现有配置访问密钥。

台账日期为人工填写，不会自动反映实际服务状态。HTTPS 检查使用系统信任链及域名验证，证书过期、不受信任或网络异常都可能导致检查失败。系统状态为最后一次执行摘要，不代表当前实时健康。请配置独立的证书到期、任务失败与服务可用性监控，并定期演练故障恢复。

## 运行测试

在项目根目录运行（Windows 可使用 `python` 替代 `python3`）：

```sh
python3 -m unittest discover -s tests -v
```

测试包含使用本地回环连接的 Web 接口测试，以及模拟的 Certbot、Nginx 超时恢复和证书验证测试；不会续期或变更真实证书。测试通过不代表真实 Linux、systemd、Certbot、Nginx 和 CA 的端到端流程已验证。上线前仍需按照 [Linux 部署指南](DEPLOY-LINUX.md)在独立测试环境演练。
